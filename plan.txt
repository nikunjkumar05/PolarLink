5. Days 4–7: make search useful
Implement keyword search first, then semantic retrieval.
The retrieval sequence should be:
1. Apply access restrictions and selected filters.
2. Retrieve candidate passages using keywords and embeddings.
3. Combine and rank the results.
4. Return passages with their document version and location.
5. Open the cited page or timestamp when clicked.
Store evidence carefully from the beginning:
asset → immutable version → evidence passage → generated claim → draft revision
For a PDF, evidence includes the page and passage. For a video, it includes the transcript interval. For a dataset, it includes the relevant table/column/row reference where applicable.
Completion check: every search result opens the correct source location. Start recording failures in a shared evaluation sheet.
6. Week 2: build generation and review
Support two formats initially:
- A short website article.
- A social-media draft.
Provide a choice of audience, such as school students or the general public.
Generate a structured response containing:
- Draft text.
- Individual factual claims.
- Supporting evidence IDs for those claims.
- Missing evidence or unresolved questions.
The backend should reject nonexistent evidence IDs. That check confirms references exist; it does not prove the cited passage supports the claim. Reviewers must be able to inspect both side by side.
Build this workflow:
Draft → Submitted for review → Changes requested / Approved → Published
Approval should apply to a specific draft revision. Editing an approved draft should require another review.
Add simple checks for numbers, units, dates and locations. Display suspected mismatches to the reviewer rather than treating an automated checker as infallible.
Completion check: a teammate can generate, correct, approve and publish an article while following its citations.
7. Week 3: implement source-update tracking
This is your proposed distinguishing feature.
When a source changes:
1. Preserve the old version.
2. Create a new version with a file hash and timestamp.
3. Find drafts and publications citing the old version.
4. Mark them “Source updated—review required.”
5. Show old and new evidence to the reviewer.
6. Re-index the new version while preserving historical citations.
Start conservatively: flag all content linked to the changed document.
Then improve precision by matching sections or paragraphs across versions and flagging claims linked to changed passages. Build this second step only after the conservative workflow works reliably.
Use a clearly labelled test document for the correction demonstration.
Completion check: updating a source reliably finds linked content without deleting its previous evidence.

9. Week 4: evaluate and prepare the demonstration
Prepare a small labelled benchmark—for example, 50 questions, including 10 that the collection cannot answer. Keep some questions untouched until final testing.
Measure	What to check
Retrieval quality	Does the correct supporting passage appear among the top results?
Citation correctness	Does the passage actually support the generated claim?
Unsupported questions	Does the system acknowledge missing evidence?
Update detection	Does it flag affected content, and how often does it over-flag?
Editorial effort	How many factual corrections are required per draft?
Time saved	How long does the same task take manually versus with your system?


Use human-labelled answers and reviews as your reference. Report measured results, including failures.
